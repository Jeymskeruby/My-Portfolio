Overview

A .NET 8 (VB.NET, WinForms) desktop application for a school guidance office: student records, guidance case tracking, incident reports from a companion mobile app, dashboards, Word/Excel document generation, and user management. The build shown here runs fully offline with pre-loaded sample data — no cloud services, credentials, or network calls.

Who it's for

  • Admin — full access plus user management and reporter contact details.
  • Staff — records, cases, reports, and templates; reporter contact details hidden.
  • Student / reporter — files incident reports from a separate companion mobile app.

Original architecture

  • .NET 8 VB.NET WinForms desktop app with hand-drawn custom chrome and a centralized UiTheme module.
  • Local SQLite for student/case data; a Word-Interop path for generating official documents from templates.
  • Firebase/Firestore for the incident-report collection written by the companion mobile app, push notifications back to reporters, and cloud backup/restore.
  • Real credential login (PBKDF2-SHA1) with an append-only audit log.

From production to public demo

  • Replaced credential login with a click-a-role picker (Admin / Staff); sessions and audit entries are still written locally.
  • Removed Firebase / Firestore / gRPC — the incident-report store, backup, restore, and notification features are backed locally or disabled.
  • Added a deterministic seeder (DemoSeeder.vb): 12 students with guardians and academic history, 18 guidance cases, 10 incident reports spread across statuses, plus demo users — rebuilt by a Reset Demo Data action.
  • A template bootstrapper generates working Word templates on first run; exports and generated files are redirected under the user's Documents folder.
  • All data is fictional sample data — no real student records.

Architecture highlights

  • UiTheme.vb — one module owning the palette (brick red / gold), typography, and a retrofit theming pass applied across every form.
  • Template manager — a card grid of .docx templates with create/import/edit, persisted in templates.json; case and incident exports merge {Placeholder} fields.
  • Incident lifecycle — reports move unseen → on-process → resolved; first open auto-advances and records an acknowledgement; exporting a report marks it resolved.
  • Dashboard — stat tiles plus a chart with annual/yearly/monthly toggles and a colour-coded "students at risk" table.

A self-contained Windows x64 build is being packaged. It needs no runtime install; on first launch Windows SmartScreen may prompt — choose More info → Run anyway. Data files and generated documents are created under your Documents folder.

Planned: static web rebuild. A browser version of Guinayang GTMS is planned, mirroring the Relay Helpdesk conversion — a localStorage data layer, the DemoSeeder dataset ported to JavaScript, the ~8 screens rebuilt buildless, and document export replaced with client-side CSV plus a print-to-PDF view.
