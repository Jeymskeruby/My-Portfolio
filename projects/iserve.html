iServe

A volunteer-matching platform — volunteers ↔ event organizers ↔ admin moderation — with skill-based matching, event join and approval flows, and a notifications centre.

Overview

iServe is a volunteer-matching platform (volunteers ↔ event organizers ↔ admin moderation), originally built as a commissioned full-stack project with a Firebase (Firestore + Auth) backend.

Who it's for

  • Volunteer — builds a skills profile, browses events, requests to join.
  • Organizer — creates events, reviews and approves join requests.
  • Admin — moderates the platform and approves pending organizers.

Original architecture

  • Firebase Firestore for all data; Firebase Auth for email/password sign-in.
  • Multi-page site; shared Web Components for the header/footer; Alpine.js for interactivity; Tailwind for styling.
  • Live Firestore onSnapshot listeners driving dashboards and the notifications centre.

From production to public demo

  • Removed the live Firebase SDK and the real project's API key/config.
  • Added mock-firebase.js — an in-browser re-implementation of the small slice of the Firebase Auth + Firestore API this app actually uses (collection().where().orderBy().limit().get(), doc().set()/.update()/.delete(), onSnapshot(), FieldValue.serverTimestamp()/increment()/arrayUnion()/arrayRemove(), email/password auth) backed by localStorage instead of a network call.
  • Added mock-seed-data.js — fictional demo volunteers, organizers, events, join requests, and notifications.
  • Added demo-banner.js — an on-page banner with the demo logins and a Reset Demo Data button.
  • The rest of the app's logic (matching, dashboards, forms, notifications) is unmodified original code.

Architecture highlights

  • Chainable mock query builder — where / orderBy / limit / get plus onSnapshot, so the original component code runs against the mock unchanged.
  • Web Components for a shared header/footer across every page of the multi-page app.
  • getRootPrefix() — a small helper that resolves relative asset paths whether the site is served from the domain root or a sub-path, which is why the demo drops cleanly under /iserve/.

Data persists in your browser's localStorage as you click around, so an organizer approving a request shows up on that volunteer's dashboard. Reset Demo Data in the banner restores the starting state.

Heads-up: this demo loads Tailwind, Alpine, and Feather Icons from a CDN and the Inter font from Google Fonts, so it needs a network connection to render fully. The portfolio site itself has no such dependency.
