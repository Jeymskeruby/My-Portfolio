Relay Helpdesk

A multi-role IT helpdesk and ticketing platform — categorised intake, an ITSM priority matrix, capacity-aware routing, SLA escalation, time tracking, a knowledge base, and an append-only audit log.

Laravel 13Inertia + React Filament v5PostgreSQL Laravel Reverb (WebSockets)

Overview

Relay Helpdesk is a multi-role IT helpdesk / ticketing platform (Client, Agent, Team Leader, Admin, Super Admin): categorised ticket intake, an ITSM urgency × impact priority matrix, capacity-aware round-robin routing, automatic SLA breach escalation, time tracking, a knowledge base, an append-only audit log with CSV/Excel export, and in-app notifications. Originally built as a commissioned full-stack project on Laravel 13 + Inertia/React + a Filament v5 admin console, with PostgreSQL and Laravel Reverb (WebSockets).

Who it's for

  • Client — raises tickets, tracks status, browses the knowledge base.
  • Agent — works an assigned queue, logs time, resolves with a proof photo.
  • Team Leader — oversees a team's queue and capacity.
  • Admin / Super Admin — manage categories, the priority matrix, SLA policy, routing rules, users, and the audit log.

Original architecture

  • Laravel 13 application, Inertia + React front end, Filament v5 admin console.
  • PostgreSQL for persistence; migrations + seeders.
  • Laravel Reverb for WebSocket delivery of live updates and notifications.
  • Server-enforced business rules: priority matrix, routing capacity limits, SLA checks, role guards.

From production to public demo

  • Deleted the entire Laravel / Filament / Inertia backend and the Vite + Tailwind build step.
  • Split the single-file working prototype into a buildless, multi-file vanilla-JS static site — index.html + css/app.css + ~30 ordered js/*.js modules, one per section of the original script (storage, seed data, routing, SLA/system checks, time tracking, notifications, auth, one file per rendered view).
  • Replaced the prototype's window.storage host API with a localStorage-backed layer in js/storage.js: the whole database lives under one versioned JSON key; skGet/skSet/loadDB stay async so every call site is unchanged; an in-memory fallback keeps the app usable in private browsing.
  • Added js/demo-banner.js — a persistent banner on every view (including the admin screens) with the demo logins and a Reset Demo Data button.
  • Everything else — ticket lifecycle, routing engine, capacity limits, priority matrix, SLA logic, time tracking, notifications, team/category/user management, KB, audit-log export — is the unmodified prototype.

Architecture highlights

  • ITSM priority matrix — a live urgency × impact grid the admin edits; the client's new-ticket form reflects it immediately.
  • Routing engine — round-robin across eligible agents with a per-category capacity limit (an agent at their limit is skipped; freed when their ticket resolves).
  • SLA system checks — a periodic pass escalates breached tickets and auto-closes resolved ones.
  • Cross-role sync — a ~6-second poll re-reads the store so an agent's public reply appears on the client's ticket a few seconds later.
